# Todo In-Memory Console Application Constitution

## Core Principles

### Spec-Driven Development (SDD)
No feature may be implemented without an explicit written specification. All behavior must originate from Markdown-based specs. Specs must be refined iteratively until the generated output is correct.

### No Manual Coding Rule
The human developer MUST NOT write application code manually. All Python source code must be generated by Claude Code. Manual edits to generated source files are strictly forbidden.

### Iterative Refinement
If generated code is incorrect or incomplete, the spec must be updated. The solution is always to improve the spec, never to patch the code manually.

### Architecture Constraints
Project must follow clean and readable Python project structure. Business logic must be separated from input/output handling. Code must be modular and maintainable.

### Claude Code Usage Rules
Claude Code must be used to generate project structure, Python source code, and CLI interaction logic. Generated code must prioritize clarity, readability, and simplicity.

### Quality Standards
The application must run without errors. CLI interactions must be user-friendly and self-explanatory. Code must follow clean code principles: clear naming, single responsibility, minimal complexity.

## Scope of Phase I
A command-line (console) based Todo application with data stored in memory only. Supported features: Add Task, View Task List, Update Task, Delete Task, Mark Task as Complete/Incomplete.

## Documentation Requirements
The repository must contain this constitution, feature specifications, implementation plans, task lists, and prompt history records.

## Governance
This constitution governs the development of Phase I. All development must follow these principles. Amendments require explicit documentation and approval.
