# Constitution – Multi-Phase Development

## 1. Governance Structure
This project follows a phased evolution. Each phase is governed by its specific modular constitution.

- **Phase I**: Console Application (Legacy)
- **Phase II**: [Full-Stack Web Application](./constitution.md) (Standard Web)
- **Phase III**: [Todo AI Chatbot](./constitution-phase-iii.md) (Agentic/MCP)

---

## 2. Phase II Objective (Operational)
Transform the in-memory console Todo application into a **full-stack, multi-user web application** with persistent storage and authentication, using **strict Spec-Driven Development**.

---

## 2. Core Principles

### 2.1 Spec-Driven Development (Mandatory)
- No feature may be implemented without an explicit written specification.
- All behavior must originate from Markdown-based specs.
- Specs must be refined iteratively until the generated output is correct.

### 2.2 No Manual Coding Rule
- The human developer MUST NOT write application code manually.
- All source code must be generated by Claude Code or specialized agents.
- Manual edits to generated source files are strictly forbidden.

### 2.3 Iterative Refinement
- If generated code is incorrect or incomplete, the spec must be updated.
- The solution is always to improve the spec, never to patch the code manually.

---

## 3. Architecture & Tech Stack

### 3.1 Backend
- **Framework**: Python (FastAPI or similar, as determined during planning).
- **Storage**: Neon PostgreSQL (Relational).
- **API Style**: RESTful.

### 3.2 Security & Authentication
- All API interactions must require a valid JWT token.
- JWT must be issued by Better Auth.
- Backend must validate JWT signature using shared secret.
- Users can only access and modify their own tasks.
- Unauthorized requests must return `401 Unauthorized`.

---

## 4. Quality & Documentation
- The application must run without errors.
- Code must follow clean code principles: clear naming, single responsibility, minimal complexity.
- The repository must contain this constitution, specifications, implementation plans, tasks, and prompt history records (PHRs).

---

## 5. Acceptance Criteria
Phase II is considered complete when:
- All features are implemented via Claude Code/Agents.
- REST APIs follow the defined contract.
- Authentication and user isolation are enforced.
- Data is persisted in Neon PostgreSQL.
- Specs, plans, and tasks are documented.
- Application runs successfully end-to-end.

---

## 6. Continuity & Governance
This Constitution preserves the intent of Phase I while elevating the project to an **AI-native, agent-governed, spec-driven system**. All future phases will build upon this foundation.
