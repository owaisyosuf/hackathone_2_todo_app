## Prompt

```text
# Specification: Phase I – In-Memory Todo Console Application

## 1. Overview
This specification defines the functional and behavioral requirements
for Phase I of the "Evolution of Todo" project.

The application is a Python-based console Todo app that stores all data
in memory and is implemented strictly using Spec-Driven Development
with Claude Code and Spec-Kit Plus.

---

## 2. Functional Requirements

### 2.1 Add Task

**Description**
The system must allow the user to create a new todo task.

**Inputs**
- Task title (required)
- Task description (optional)

**Behavior**
- A unique task ID must be automatically generated.
- The task must be marked as incomplete by default.
- The task must be stored in memory.

**Validation Rules**
- Title must not be empty.
- Description may be empty or omitted.

---

### 2.2 View Task List

**Description**
The system must display all existing tasks in the console.

**Behavior**
- Each task mu persistence is allowed.

### 3.2 Interface
- The application must use a text-based console interface.
- Menu options must be clearly displayed.
- User input prompts must be simple and understandable.

### 3.3 Reliability
- The application must not crash due to invalid input.
- All errors must be handled gracefully with user-friendly messages.

---

## 4. Application Flow

1. Display main menu:
   - Add Task
   - View Tasks
   - Update Task
   - Delete Task
   - Toggle Complete
   - Exit

2. User selects an option.
3. System executes the corresponding operation.
4. Control returns to the main menu until exit is selected.

---

## 5. Constraints

- Manual code writing is strictly prohibited.
- All implementation must be generated by Claude Code.
- Any change in behavior must be done by updating this spec.

---

## 6. Definition of Done

This specification is considered fulfilled when:
- All five core features function correctly.
- The application runs successfully in the console.
- All behavior matches this specification exactly.
```
