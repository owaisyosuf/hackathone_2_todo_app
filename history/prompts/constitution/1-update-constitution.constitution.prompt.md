# Constitution: Phase I – Todo In-Memory Console Application

## 1. Purpose
This constitution governs the development of Phase I of the "Evolution of Todo" project.
The goal is to build an in-memory Python console-based Todo application using
Spec-Driven Development with Claude Code and Spec-Kit Plus.

The human developer acts strictly as a Product Architect and Spec Author.
All implementation code must be generated by Claude Code.

---

## 2. Core Development Principles

### 2.1 Spec-Driven Development (SDD)
- No feature may be implemented without an explicit written specification.
- All behavior must originate from Markdown-based specs.
- Specs must be refined iteratively until the generated output is correct.

### 2.2 No Manual Coding Rule
- The human developer MUST NOT write application code manually.
- All Python source code must be generated by Claude Code.
- Manual edits to generated source files are strictly forbidden.

### 2.3 Iterative Refinement
- If generated code is incorrect or incomplete, the spec must be updated.
- The solution is always to improve the spec, never to patch the code manually.

---

## 3. Scope of Phase I

### 3.1 Application Type
- A command-line (console) based Todo application.
- Data must be stored in memory only (no database, no file persistence).

### 3.2 Supported Features (Basic Level)
The application must support the following core Todo features:

1. Add Task
   - Create a new task with a title and optional description.

2. View Task List
   - Display all tasks with unique IDs.
   - Show completion status clearly.

3. Update Task
   - Modify task title and/or description.

4. Delete Task
   - Remove a task using its ID.

5. Mark Task as Complete / Incomplete
   - Toggle task completion status.

---

## 4. Data Model Principles

- Each task must have:
  - A unique identifier
  - Title
  - Optional description
  - Completion status (complete / incomplete)
- Task data exists only for the duration of the program execution.

---

## 5. Architecture Constraints

### 5.1 Project Structure
- The project must follow clean and readable Python project structure.
- Business logic must be separated from input/output handling.
- Code must be modular and maintainable.

### 5.2 Technology Stack
- Python 3.13 or higher
- UV for environment and dependency management
- Claude Code for code generation
- Spec-Kit Plus for specification management

---

## 6. Claude Code Usage Rules

- Claude Code must be used to:
  - Generate project structure
  - Generate Python source code
  - Generate CLI interaction logic
- Claude Code must respect this constitution and all written specs.
- Generated code must prioritize clarity, readability, and simplicity.

---

## 7. Quality Standards

- The application must run without errors.
- CLI interactions must be user-friendly and self-explanatory.
- Code must follow clean code principles:
  - Clear naming
  - Single responsibility
  - Minimal complexity
